# Playable Key Moments — Phase 1 POC evidence

**Programme:** `docs/plan/playable-key-moments-roadmap.md`  
**Implementation PR:** #36 — `feat/playable-key-moments-poc`  
**Scope:** Phase 1 only; no durable career persistence and no continuous 11v11 control.

## Decision summary

Phase 1 has proved the load-bearing engineering hypothesis: a real Pitch match can stop after authoritative phase preparation but before terminal shot resolution, accept bounded normalized user intent, commit the result once to the existing authoritative ledger, and resume through the normal discipline/injury/substitution flow without creating a second match engine.

The selected renderer for the POC is **Three.js 0.185.1 (MIT)**. The PlayCanvas comparison spike was removed from the production graph after the decision.

### Why Three.js won the bounded renderer comparison

Both candidates rendered the same repository-owned procedural scene contract, so the comparison did not depend on different models or animation assets.

| Criterion | Three.js 0.185.1 | PlayCanvas 2.22.0 | Decision |
|---|---:|---:|---|
| Licence | MIT | MIT | tie |
| POC adapter production chunk before engine load | ~5.09 kB | ~5.20 kB | tie |
| Published minified ESM engine payload | **356.98 kB** | **2.35 MB** | Three.js |
| Extra engine/editor workflow required | none | none | tie |
| Capability needed by this POC | sufficient | sufficient | tie |
| Adapter complexity for this scene | smaller/simpler | broader engine lifecycle | Three.js |

Published payload evidence:

- Three.js exact-version jsDelivr listing: `https://cdn.jsdelivr.net/npm/three@0.185.1/build/` (`three.module.min.js` = 356.98 kB).
- PlayCanvas exact-version jsDelivr listing: `https://cdn.jsdelivr.net/npm/playcanvas@2.22.0/build/` (`playcanvas.min.mjs` = 2.35 MB).

The surviving POC URL is pinned to `https://cdn.jsdelivr.net/npm/three@0.185.1/build/three.module.min.js`. Phase 2 should move the chosen renderer into the ordinary package/build graph before the feature becomes a durable career surface, so dependency integrity is owned by the repository lockfile rather than a runtime CDN.

## Asset and animation provenance

Phase 1 intentionally uses **no downloaded football player, goalkeeper, stadium or animation assets**. The pitch, goal, ball, shooter, defender and goalkeeper are created procedurally in repository code. Strike, run-up, defender lunge, keeper dive and recovery are deterministic transforms generated by `playableMomentsPocScene.js`.

Consequences:

- no paid asset is present;
- no Blender/manual animation pipeline is required;
- no third-party model/animation licence needs to be carried into Phase 2;
- the only third-party runtime input is the exact-version MIT Three.js engine.

This is deliberate for the POC. Phase 2 may introduce approved free/CC0 production assets only after a provenance manifest and deterministic conversion pipeline are defined.

## Authoritative continuation contract proved

The POC introduces a three-stage domain seam:

1. `prepareAuthoritativePhase()` resolves possession, route, actors, success and chance context but does **not** decide the shot finish.
2. `buildPlayableMoment()` projects a deterministic pre-outcome scene from that prepared context.
3. `commitAuthoritativePhase()` resolves either the unchanged automatic finish or bounded interactive attack/goalkeeper intent and produces the existing authoritative ledger/event contract.

`resolveAuthoritativePhase()` remains the compatibility wrapper around prepare + commit. Normal Quick Sim / Watch callers therefore keep the established automatic path.

`simulateMatchSegment()` can suspend only when explicit POC control requests a **single phase** and an eligible controlled-team moment is prepared. The suspension snapshot contains the already-allocated phase/RNG/fitness state but publishes none of it. `resumePlayableMatchPhase()` restores that snapshot, commits the shot once, then runs the normal post-action discipline/injury/substitution logic.

## Production-load isolation

The POC is mounted only when `?playable-poc=1` is present. `src/main.js` dynamically imports `PlayableMomentsPoc.svelte`, and that component dynamically imports the Three.js adapter. The 3D renderer is therefore absent from ordinary management startup.

The successful Vite build before the renderer decision showed the POC as separate lazy chunks rather than part of the base app. The final single-renderer build must retain that shape; CI is the build gate and the PR preview is the manual verification surface.

## Honest completion boundary

**Engineering/architecture Phase 1 is PASS.** The POC is implemented, selected to one renderer, provenance-safe for the spike, isolated from normal product load, and green through the full automated football regression suite.

The roadmap deliberately made rendered/mobile/game-feel observation a non-automatable acceptance item. This agent environment has Chromium installed but cannot resolve external hosts, and the repository explicitly prohibits adding browser/E2E automation. Therefore this document does **not** invent frame-time, touch-device or subjective animation-quality measurements.

Before treating Phase 1 as a full product-acceptance PASS and starting persistence-heavy Phase 2 work, open the branch preview on a real phone/browser and record:

- browser/device/network;
- cold `Ready` time;
- p95 frame time after a representative shot;
- 20× lifecycle result;
- synthetic attack usability;
- synthetic goalkeeper usability;
- one real open-play pause → action → commit → next-moment flow;
- visible agreement between miss/save/goal and ball/keeper contact;
- whether strike/dive/recovery quality is promising enough to continue.

No code or architecture change should be needed to collect that final evidence; the instrumentation is already in the POC surface.

## Phase 2 fence

Do **not** extend this PR into durable career persistence, full moment pacing, set pieces, multiple scenario families, production model/animation ingestion, audio/replays or continuous football control. Those are later phases and should begin only from the reviewed Phase 1 continuation contract.
