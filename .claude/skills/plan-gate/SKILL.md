# plan-gate: no edits until the plan exists

CI's 1180 checks catch a known set of regressions, not the shape of a bad idea.
A mistake in the save schema, the event queue, or the module load order isn't
something a red check flags cleanly — it's the game breaking for whoever loads
it next, or a save that silently stops opening. This gate forces "what does
this actually touch" to surface before anything changes, when it's still free.

## The gate

Before your first edit, write a plan in your response:

```
GOAL: <one sentence: what is true when this is done>
UNKNOWNS: <what you haven't verified yet, and how you'll verify it>
TOUCHES: <which files/modules, and which side of the modules//ui/ boundary
          each is on today, or its post-migration equivalent>
SUCCESS CRITERIA: <how you'll know it worked - validate.js staying green,
                   a manual check, an observable in the running app>
OUT OF SCOPE: <adjacent things noticed but not touched - see scope-fence>
```

Rules:
1. **From evidence, not memory.** Read the actual files before planning —
   this repo is mid-migration (see `docs/plan/`) and assumptions about where
   logic lives go stale fast, phase to phase.
2. **Every unknown gets a verification step.** "Probably reads from
   `save.pendingEvents`" is not a plan line; "check `gameweek.js`'s queue shape"
   is.
3. **More than ~7 steps → decompose the task**, don't write a longer plan.
4. **Reality contradicts the plan mid-task → STOP and re-plan.** State what
   changed, update the plan, continue.

## When this applies

Gate it:
- **The IndexedDB schema** (`src/modules/db.js`) — currently at `DB_VERSION = 3`
  with 8 object stores and no migration path. A schema change without a
  migration orphans every existing save.
- **The event queue** (`save.pendingEvents`, built and drained in
  `src/modules/gameweek.js`) — one button press pops exactly one event; the
  gameweek advances only when the queue is empty, and cup opponents are
  pre-drawn when it's built. Getting this wrong breaks cups and Europe
  silently, not loudly.
- **Simulation math** — `matchEngine.js`, `standings.js`, `promotion.js`,
  `cups.js`.
- **The module load order** — `src/build.py`'s `MODULES` list today; the
  equivalent import graph once Phase 2 of the rebuild lands.
- **The data pipeline** — `tools/csv-to-league.mjs` and `tools/reconcile.mjs`
  (Node; replaced `src/csv_to_league.py` in Phase 6).
- **The footy-sim roster reconciliation's attribute mapping**
  (`tools/lib/rating.mjs`, calibrated weights in `tools/weights.json`,
  regenerated by `tools/calibrate-weights.mjs`) — Phase 6 delivered this, but
  re-running it or changing the weights still derives every player's rating
  from a different attribute set than a hand-edited CSV would, so it changes
  match outcomes across the
  whole game if the weights are off.

Skip it: adding/editing player or team data through the existing CSV pipeline,
a UI-only change contained to one screen, a CSS tweak, fixing an obvious bug in
one function. Say "skipping plan-gate: routine" when you skip on judgment —
and stop the moment a "routine" task surprises you.
